# CVAT Zombie 标注协作手册

适用项目：MineCombat Zombie Detector  
标注对象：Minecraft 128×128 Policy RGB 画面中的 Zombie  
标签：`zombie`（唯一类别）  
工具：https://app.cvat.ai

---

## 1. 先理解任务结构

```text
Project：MineCombat Zombie Detection
  └── Task：一批图片，例如 trainval_calibration_10
        └── Job：实际打开进行标注的页面
```

- **Project**：定义标签，只有 `zombie`。
- **Task**：一组图片，例如 10 张校准图或 40 张训练图。
- **Job**：每个标注人员实际打开的页面。

不要自己新建 Project。项目负责人会创建 Project/Task，并把链接或任务分配给你。

---

## 2. 开始标注前的准备

1. 注册/登录 `https://app.cvat.ai`。
2. 把 CVAT 用户名发给项目负责人，等待被加入项目。
3. 打开负责人给你的 **Job 链接**。
4. 确认左侧/右侧标签是 `zombie`。
5. 确认当前是 **Rectangle / Shape** 模式，不要使用 Track。

> **非常重要：这是图片任务，不是视频任务。请画独立的 Rectangle Shape，不要使用 Track。**  
> Track 会在多帧之间插值，容易产生重复框和空帧错误。

---

## 3. 标注操作

### 画新框

1. 选择左侧工具栏的 **Rectangle**。
2. 在 Zombie 左上角按住鼠标，拖到右下角。
3. 松开后确认标签是 `zombie`。
4. 拖动框边缘的控制点微调。
5. 保存。

### 修改已有框

- 选中框，拖动边缘/角点调整。
- 如果框里包含背景，缩小到 Zombie 的可见轮廓。
- 如果框太小，扩大到完整可见身体。
- 标签错误时改成 `zombie`。
- 多余框直接删除。

### 删除和撤销

- 删除：选中框后按 Delete。
- 撤销：`Ctrl+Z`。
- 保存：点击 Save；CVAT 通常会定时自动保存，但不要完全依赖自动保存。

### 切换图片

使用页面底部的上一张/下一张按钮，或界面提示的导航快捷键。

---

## 4. 框选规范

### 正样本

框住 Zombie 的**完整可见身体**：

- 头部、躯干、四肢
- 不包含 HUD、准星、物品栏
- 不包含无关背景
- 目标被画面边缘截断时，框到画面边界
- 目标被树/方块遮挡时，框可见部分，不猜测完全不可见的身体
- 极远目标：框住所有可辨认的 Zombie 像素
- 多个 Zombie：每个 Zombie 单独一个框

### 负样本

画面中没有 Zombie：

- 不画任何框
- 保存为空
- 不要在背景中画“可能存在的区域”

### 不要标的内容

- 苦力怕、骷髅、蜘蛛、末影人
- 玩家、动物、掉落物
- HUD、物品栏、准星、文字
- 只是“像 Zombie”的绿色/阴影区域，无法确认时不要硬标

### 特殊情况

| 情况 | 处理 |
|---|---|
| 目标只露出一部分但能确认是 Zombie | 标，框可见部分 |
| 目标极远、只有几像素 | 放大后框住全部可辨认像素 |
| 目标非常近、被画面截断 | 框到画面边缘 |
| 目标被树/方块遮挡 | 框可见部分，不补画不可见身体 |
| 不确定是否为 Zombie | 不要猜；记录问题，交给负责人确认 |
| 同一画面多个 Zombie | 每个单独一个 Shape |

## 5. 预标注怎么处理

项目负责人可能会导入模型预标注。预标注只是**候选框**，不是最终答案。

每张图都要检查：

- 框正确：保留或微调
- 框偏大/偏小：调整
- 漏检：补画
- 错误类别：改成 `zombie` 或删除
- 重复框：删除多余的
- 无目标：保持空

**不要保留预标注 + 新画的重复框。**  
一帧一个 Zombie 只能保留一个最终框。

---

## 6. 常见错误

### 错误 1：使用 Track

这是图片任务。Track 会产生多帧插值，导致：

- 某些帧出现不该有的框
- 负样本被自动填框
- 导出时出现重复/错误标签

**正确做法：使用 Rectangle Shape，每帧独立标注。**

### 错误 2：预标注和手工框重复

如果模型已经给了一个框，调整它，不要在旁边再画一个。  
最终每帧只保留一套框。

### 错误 3：框太松

框里包含大量草地、树木或 HUD，会降低训练质量。  
框应贴近 Zombie 的可见轮廓。

### 错误 4：漏掉空负样本

没有 Zombie 的图片也必须保存为空标签。  
空负样本对降低误报很重要。

### 错误 5：标注其他 mob

本项目只训练 `zombie`。  
苦力怕、骷髅、蜘蛛、末影人都不标。

### 错误 6：改动测试集

最终测试集在训练前冻结。  
测试集标注完成后，不要为了“让模型好看”再修改。如果发现错误，先报告负责人。

- [ ] 当前图片有且只有正确的 `zombie` 框
- [ ] 框包含完整可见 Zombie
- [ ] 框不包含 HUD/背景
- [ ] 没有重复框
- [ ] 没有 Track
- [ ] 负样本保持空白
- [ ] 已保存
- [ ] 已切到下一张

全部完成后：

```text
10 张完成
```

或按负责人约定的格式汇报。

## 8. 导出和交付

### 标注人员

通常**不需要导出**。  
项目负责人会通过 CVAT API 统一导出，避免格式不一致。

### 项目负责人

使用 YOLO 1.1 导出，单类别标签：

```text
0 center_x center_y width height
```

注意：CVAT 免费版可以导出标注，但**不能导出带图片的数据集**。  
图片我们本地已有，所以只导出标注即可。

导出后必须检查：

- 每张图都有对应 `.txt`
- 负样本 `.txt` 为空
- 类别只有 `0`
- 坐标归一化在 `[0, 1]`
- 无重复框
- 无 Track
- Train/Val/Test 无 Episode 重叠
- Test labels 已冻结

---

## 9. 协作和任务分配

### 项目负责人

- 创建 Project 和 Task
- 邀请标注人员
- 提供 Job 链接
- 上传预标注
- 导出和格式校验
- 维护 Train/Val/Test 划分
- 冻结 Test 标注

### 标注人员

- 只使用分配给自己的 Job
- 按本手册标注
- 使用 Rectangle Shape，不使用 Track
- 不修改其他 Job
- 不导出图片
- 遇到不确定目标先标记/报告

### 重要规则

- Train/Val/Test 按 Episode 划分，不能按图片随机拆
- 同一个 Episode 不能跨 split
- Test 不参与训练和调参
- 之前 80 张审核集不进入 Train/Val
- 所有标注文件需要版本记录
